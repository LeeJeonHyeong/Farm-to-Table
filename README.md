# Farm-to-Table 역경매 매칭 플랫폼 (프론트엔드 데모)

셰프가 원하는 식자재 조건을 "딜"로 등록하면, 농가가 가격과 조건을 제안하고, 셰프가 그중 하나를 선택해 거래를 확정하는 역경매 방식 데모입니다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173` 으로 접속하면 됩니다.

## 프로젝트 구조

```
.
├── index.html
├── package.json
├── vite.config.js
└── src
    ├── main.jsx       # React 엔트리포인트
    └── App.jsx        # 전체 앱 (단일 파일 컴포넌트)
```

지금은 의도적으로 모든 화면 컴포넌트를 `App.jsx` 한 파일에 몰아넣은 상태입니다. 기능이 더 늘어나면 `src/components/`, `src/screens/` 등으로 분리하는 걸 권장합니다.

## 핵심 흐름 (역경매 구조)

1. **딜 만들기** — 셰프가 5단계 위저드로 요청서 작성 (레스토랑·품목 → 품질조건 → 수량 → 납품일·가격 → 확인)
2. **딜 찾기** — 농가가 모집중인 딜 목록을 보고 가격·조건을 담아 제안서 제출
3. **내 거래** — 셰프가 들어온 제안들을 가격순으로 비교하고 하나를 선택 → 진행중 상태로 전환
4. 진행중 상태에서 정산 내역(선급금 30% / 잔금 70% / 플랫폼 수수료 10%, 모두 예시값)을 확인하고, 납품 확인 후 완료 처리하면 거래 타임라인이 마무리됩니다.

## 매칭에 반영된 식자재 조건

- **품목** (`CROPS`): 토마토, 바질, 블루베리, 딸기, 로메인, 로즈마리, 애호박, 고수
- **숙성도/수확 단계** (`RIPENESS_STAGES`): 품목별로 다른 단계 체계 적용 (예: 토마토는 그린→브레이커→터닝→핑크→라이트레드→레드(완숙) 6단계)
- **표준규격 등급** (`GRADE_LEVELS`): 특/상/보통 — 국립농산물품질관리원 표준규격 제도의 일반 등급 체계를 참고했습니다. **단, 품목별 정확한 판정 기준(결점과 비율 %, 중량 구간 등)은 검증되지 않았습니다.** 실제 서비스화 전에 `law.go.kr` 또는 농관원 고시 원문, `data.mafra.go.kr`(농림축산식품 공공데이터), `kadx.co.kr`(농식품 빅데이터 거래소)을 확인해 정확한 수치로 교체해야 합니다.
- **크기 조건**: 자유 텍스트 입력 (예: "지름 5cm 이상")

## ⚠️ 알아두어야 할 제약사항

### 1. 저장소(storage)는 임시 어댑터입니다

이 프로젝트는 원래 Claude.ai Artifacts 환경(`window.storage` API)에서 만들어졌습니다. 그 API는 일반 브라우저에는 없기 때문에, `App.jsx` 상단에 **localStorage로 대체하는 어댑터**를 넣어뒀습니다.

```js
const storage = window.storage ? window.storage : { get, set 어댑터 (localStorage 기반) };
```

이 상태로는:
- 데이터가 **브라우저 하나에만** 저장됩니다 (다른 사람과 공유 안 됨, 캐시 삭제하면 사라짐)
- 여러 명이 동시에 쓰는 실제 서비스로는 부적합합니다

**다음 단계**: `storage.get` / `storage.set` 호출 부분을 실제 백엔드 API(`fetch("/api/deals")` 등)로 교체하세요. 데이터 구조(딜 객체 shape)는 그대로 유지해도 됩니다.

### 2. 사용자 인증이 없습니다

지금은 누구나 모든 딜을 보고, 누구나 어떤 딜의 제안이든 선택할 수 있습니다. 실제 서비스에서는 셰프/농가 로그인과 권한 분리가 필요합니다 (자기가 만든 딜만 선택 가능하도록).

### 3. 매칭은 전부 사람이 보고 판단하는 구조입니다

현재는 "농가가 직접 보고 제안 → 셰프가 직접 보고 비교·선택"하는 수동 매칭입니다. AI 기반 추천/점수화는 아직 들어가 있지 않습니다 (이전 버전에서 규칙기반 점수 매칭을 시도했었는데, 와이어프레임 피드백을 반영해 역경매 방식으로 구조를 바꾸면서 제외했습니다. 필요하면 `git log`나 이전 대화 내용을 참고해 다시 붙일 수 있습니다).

## 지금까지 진행 이력 (요약)

1. 사업계획서 분석 → 시스템 아키텍처 다이어그램, 12개월 개발 로드맵 작성
2. 셰프 수요입력 + 농가 매칭 데모 (규칙기반 점수 매칭) 제작
3. 농가 등록 화면 추가
4. 두 화면을 탭으로 연결, 공유 상태로 통합
5. `window.storage` 연동으로 영구 저장 구현
6. 식자재 조건 추가: 숙성도/수확단계, 표준규격 등급(특/상/보통)
7. 업로드된 와이어프레임을 참고해 **역경매 구조**(딜 만들기 → 농가 제안 → 셰프 선택)로 전면 개편
8. 5단계 위저드형 딜 만들기, 진행 타임라인, 정산 내역 카드 추가
9. (현재) VS Code에서 이어 작업할 수 있도록 Vite 프로젝트로 패키징
